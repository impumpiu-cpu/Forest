# Тёплый Брод

Симуляция поселения в духе RimWorld: физические поля на сетке, навигация по полям течения и агенты с потребностями, характерами и вечерним советом у костра. Работает в браузере без зависимостей во время выполнения.

## Запуск

**Windows:** двойной клик по `Forest.bat` — новое меню (`forest.html`: Создать землю, Заселение мира, Кампания, Быстрый старт, Настройки; его строит ветка `Table`, [docs/TABLE.md](docs/TABLE.md)). `start.bat` открывает старое меню — технический полигон (`index.html`). Оба поднимают локальный сервер (Node.js, иначе Python) и открывают игру в браузере; окно сервера закрывается вместе с игрой. Если нет ни того, ни другого, запуск подскажет, что поставить.

Код написан на ES-модулях, поэтому `index.html` нельзя открыть двойным кликом (браузер не грузит модули с диска), нужен локальный сервер:

```bash
node tools/serve.mjs             # или: npm run serve  (нужен только Node.js, без зависимостей)
python3 -m http.server 8000      # то же самое на Python
# затем http://localhost:8000
```

Собранной версии в репозитории нет: игра запускается только через сервер. Если нужен один файл без сервера, его можно собрать у себя (`dist/` в git не хранится):

```bash
npm install      # один раз, ставит esbuild
npm run build    # src/ → dist/forest.html (на Windows — build.bat)
```

При запуске открывается главное меню: **Мир** — полигон глобальной карты (генерация мира по этапам с летописью сбоку; мир с летописью сохраняется в библиотеку миров браузера или файлом), **Карта** — поселение на полигоне с настройками или на выбранной клетке сохранённого мира (щелчок по суше на экране «Мир»), **Кампания** — поход каравана из выбранной столицы по сохранённому живому миру ([docs/CAMPAIGN.md](docs/CAMPAIGN.md)), **Эпическая кампания** — всё сразу: новый мир с долгой историей (три эпохи по 75–150 лет), выбор столицы и поход по нему. Кнопка «← Главное меню» (или Esc) есть на каждом экране: генерация мира останавливается и ждёт кнопки «Дальше», игра встаёт на паузу, и к ней можно вернуться. Пока это два независимых полигона; как они сошьются, записано в [docs/WORLD.md](docs/WORLD.md).

GitHub Pages работает с `index.html` напрямую: Settings → Pages → ветка `main`.

## Проверки

Всё работает без браузера, на том же ядре, что и игра:

```bash
npm test                 # ядро, справочники, логика, детерминизм, колония на 2 дня
npm run balance:standard # стандартный балансный прогон, ~5 минут на двух ядрах
npm run items            # оружие и броня на одной шкале: PL, цены, кто кого перекрывает
npm run arena            # бои без графики: оружие по тирам, коэффициент силы рас и существ
npm run arena:calibrate  # то же для КС с записью поправок в data/balance/creatures.js
```

Все команды, параметры балансного прогона и что именно проверяется — на странице [Проверки и баланс](docs/TESTING.md).

## Глоссарий

**PL (power level, уровень силы)** — сила вещи на одной шкале для оружия и брони. Один уровень — ×1,2. Дубина — PL 0.

> PL нужен, чтобы сравнивать вещи разной природы: копьё со щитом, бронзу с железом, двуручный молот с одноручным мечом. Атака оружия — во сколько раз его урон за тик (`dmg / cd`) больше, чем у дубины, в уровнях ×1,2. Защита брони и щита — во сколько раз дольше держится владелец: `1 / (1 − броня)` и так же для блока, в тех же уровнях. Атака и защита складываются, потому что сила бойца — урон за тик, умноженный на время, которое он продержится; арена это подтверждает: +1 PL атаки и +1 PL защиты дают почти одинаковую прибавку к шансу победы. Ступень материала даёт около +1 PL, качество +1 — около +0,8 PL. PL считает `npm run items` по `data/balance/rules.js`; игра его не читает. Подробнее — [Баланс вещей](docs/BALANCE.md#единая-шкала-pl).

**КС (коэффициент силы)** — сколько стоит в бою одно существо со всем, что на нём. Обычный человек с костяным копьём в лубяной одежде — 100. КС складывается: две стороны с равной суммой побеждают примерно поровну, сколько бы бойцов ни было с каждой.

> КС считает `agents/strength.js` из тех же формул, что и бой: урон за тик (удар × Сила × навык × криты / перезарядка с учётом Ловкости, плюс выстрелы и яд) умножается на стойкость (здоровье / (1 − броня) / (1 − блок) / (1 − уклонение), больше для тех, кого простое оружие берёт плохо). Произведение сравнивается с эталоном и возводится в степень `alpha` = 0,55: так в толпе, где бьют все разом, складывается сила (квадратичный закон Ланчестера). Вид может получить поправку `ks`, если формула чего-то не видит. `alpha`, вес выстрелов и `ks` всех видов подбирает арена групповыми боями (`npm run arena:calibrate`) и пишет в `data/balance/creatures.js`. На КС стоят набеги: угроза — это КС следующей банды, и банду набирают, пока сумма КС её членов не дойдёт до угрозы. Перевес в 15% уже решает бой (~94% побед). Гоблин ~80, орк ~190, огр ~275, вампир ~565; железо со щитом и кольчугой поднимает человека со 100 до ~230. Подробнее — [Баланс вещей](docs/BALANCE.md#коэффициент-силы-кс).

**Тир** — ступень материала: 0 — дерево, кость, шкуры и ткань; 1 — бронза и серебро; 2 — железо; 3 — сталь (позже); 4 — мифрил.

**Форма × материал** — из чего собран предмет: форма (копьё, кольчуга) задаёт профиль, материал (кость, железо, мифрил) — тир и множители. Новая форма есть во всех подходящих материалах, новый материал — во всех подходящих формах ([Баланс вещей](docs/BALANCE.md#форма-и-материал)).

**Тип удара** — колющий, рубящий или дробящий. Его задаёт форма оружия (или вид для удара без оружия); броня и щит держат одни удары лучше других (кольчуга — рез, но не булаву; щит — остриё, но не дубину; стрелы щит ловит с половиной шанса, а меч и посох их не парируют), тело тоже (копьё проходит сквозь костяка, дубина его ломает). **Чем бьёт оружие** — доли Силы и Ловкости в ударе: молот бьёт Силой, кинжал — Ловкостью ([Баланс вещей](docs/BALANCE.md#типы-удара-и-чем-бьёт-оружие)).

**Угроза** — КС следующего набега; **уровень угрозы** — насколько далеко зашёл враг: от него зависят, какие банды приходят и как они снаряжены.

## Главное правило

**Контент — это данные, системы — это код**. Всё, что можно перечислить (ресурсы, работы, черты, виды существ, постройки), лежит в справочниках `src/data/`. Системы ищут записи по `id` и не содержат списков. Новое добавляется одной записью в справочник, а не правкой систем.
