# Тёплый Брод

Симуляция поселения в духе RimWorld: физические поля на сетке, навигация по полям течения и агенты с потребностями, характерами и вечерним советом у костра. Работает в браузере без зависимостей во время выполнения.

## Запуск

Код написан на ES-модулях, поэтому `index.html` нужно открывать через локальный сервер:

```bash
python3 -m http.server 8000      # или: npm run serve
# затем http://localhost:8000
```

Для запуска без сервера есть собранная версия `dist/forest.html`: это один файл, который открывается двойным кликом. Пересобрать её можно так:

```bash
npm install      # один раз, ставит esbuild
npm run build    # src/ → dist/forest.html
```

## Проверки и балансный прогон

Всё ниже работает без браузера, на том же ядре, что и игра.

| Команда | Что делает |
|---|---|
| `npm test` | Четыре проверки подряд: ядро не зависит от экрана, ссылки в справочниках сходятся, игра детерминирована и сохранение продолжается тик в тик, колония живёт 2 дня без ошибок |
| `npm run smoke -- 10 лес` | Колония на 10 дней с сидом «лес»: что происходило по дням, снаряжение, журнал |
| `npm run determinism -- 4` | Две игры с одним сидом совпадают; сохранённая на середине игра продолжается так же, как исходная |
| `npm run balance:standard` | **Стандартный балансный прогон**: набеги нет / редкие / частые, волки стаями, 10 сидов × 30 дней |
| `npm run balance -- …` | Балансный прогон со своими параметрами: много игр параллельно, таблица и отчёт с графиками |

### Балансный прогон

Стандартный прогон — с ним сравниваем каждое изменение баланса:

```bash
npm run balance:standard
# то же самое полностью:
node tools/balance.mjs --seeds 10 --days 30 --vary raids=off,rare,often --set predators=many
```

Три варианта набегов (нет, редкие, частые) при стаях волков, по 10 сидов на 30 дней, всего 30 игр. На двух ядрах занимает около 5 минут. Отчёт ложится в `runs/<дата-время>/report.html`. Чтобы положить его в свою папку, добавьте `-- --out runs/имя`.

Свои прогоны:

```bash
npm run balance -- --seeds 12 --days 30                         # базовые настройки меню, 12 сидов
npm run balance -- --set raids=often --set predators=many       # поменять настройки для всех игр
npm run balance -- --vary raids=off,rare,often --seeds 10       # сравнить варианты
npm run balance -- --vary raids=rare,often --vary stock=poor,normal   # варианты перемножаются
```

Параметры: `--seeds N` (сиды 1…N), `--seed-base K` (сдвиг сидов), `--days N`, `--set ключ=значение` (любой ключ стартового меню из `data/presets.js`, например `size=large`, `colonists=5`, `climate=cold`), `--vary ключ=a,b,c`, `--jobs N` (потоков, по умолчанию все ядра), `--out папка`.

Игры идут в рабочих потоках, по одной на ядро. Результат — в `runs/<дата-время>/`:
- `report.html` — отчёт: итоги по вариантам, доля выживших поселений по дням, любой показатель по дням (медиана и разброс между сидами), причины смертей, скорость расчёта;
- `runs.csv` — строка на каждую игру: выжила ли, на какой день пала, все показатели на конец;
- `days.csv` — строка на каждый игровой день каждой игры, для своих графиков в таблицах;
- `summary.json` — то же, что в отчёте, для скриптов.

Что измеряется, задаёт справочник `data/metrics.js`: добавленная туда строка сама появится в CSV, отчёте и выборе показателя. Игра без экрана запускается функцией `simulate(cfg, {days})` из `src/headless.js`.

На средней карте день игры считается примерно за секунду, игра на 30 дней — за полминуты на ядро.

GitHub Pages работает с `index.html` напрямую: Settings → Pages → ветка `main`.

## Архитектура

Главное правило: **контент — это данные, системы — это код**. Всё, что можно перечислить (ресурсы, работы, черты, виды существ, постройки), лежит в справочниках `src/data/`. Системы ищут записи по `id` и не содержат списков. Новое добавляется одной записью в справочник, а не правкой систем.

### Проверка справочников

`tools/check-data.mjs` (входит в `npm test`) проверяет, что все ссылки между записями сходятся: ресурсы в ценах и рецептах, постройки в `requires` и `needs`, мастерские у рецептов и работ, значки предметов, мысли у еды. Ошибка останавливает тест с понятным текстом, а предупреждение говорит о записи, которая в игре никогда не появится (ресурс ниоткуда не добывается, предмет нельзя сделать).

### Быстродействие

Тепло и дым считаются по всей карте каждый тик, это самая дорогая часть. Снос ветром считает точку выборки для столбцов и строк один раз, а не для каждой клетки; дым не считается вовсе, пока нет огня и прежний дым рассеялся. Карта местности и слои перерисовываются несколько раз в секунду, огонь и дым — каждый кадр. Вопросы, которые за тик задают много раз (список колонистов, что колония может сделать в мастерских, какую руду копать), считаются один раз через `perTick` и лежат в `w.scratch`, который не сохраняется. Медленные кэши, которые должны пережить сохранение, лежат в `w.cache` и хранят только данные.

### Ядро и оболочка

Состояние игры — один объект `world`, который передаётся во все функции. Модули не держат глобального состояния.

Код делится на **ядро** (всё, кроме `ui/`, `render/` и `main.js`) и **оболочку**. Ядро не знает об экране: не импортирует оболочку и не трогает `document`, `window`, хранилища браузера. Это проверяет `tools/check-layers.mjs` при каждом `npm test`. Оболочка читает `world`, чтобы рисовать, а менять мир может только через `COMMANDS` из `commands.js`. Поэтому любую другую оболочку — другой рендер, сервер, бота, балансный прогон — можно подключить к тому же ядру без правок.

### Детерминизм и сохранения

Вся случайность игры идёт из одной последовательности `w.rng`. Один сид, одни настройки и одни действия игрока дают одну и ту же историю. `Math.random` в ядре не используется.

`world/save.js` превращает мир в JSON и обратно. Справочники и пресеты в сохранение не копируются, а записываются ссылкой вида `building:hut`. Живые части собираются заново: генератор продолжает с сохранённой позиции, навигация получает свои поля расстояний в том же состоянии. Поэтому загруженная игра продолжается тик в тик как исходная. Если в мир попадёт то, что нельзя сохранить (функция, экземпляр класса), сохранение остановится с точным путём к этому месту.

В браузере сохранения лежат в IndexedDB: кнопка «Сохранить», автосохранение каждое утро, список в меню. Кнопка «В файл» скачивает сжатое сохранение (на средней карте около 450 КБ), а меню открывает его обратно.

### Граница с внешним миром

Локальная карта общается с остальным миром только через `outside/`:
- **внутрь** приходят группы: переселенцы, звери, налётчики (позже послы, торговцы, поручения);
- **наружу** уходит ежедневный отчёт колонии: жители, оружие, броня, постройки, запасы (позже дань и послы).

У каждого прибытия две половины. **Предложение** — кто выходит в путь и когда — решает поставщик за границей. **Приём** — сколько из них останется — решает местная запись в `data/migrations.js`: есть ли место и еда, прокормят ли луга ещё зайцев, нет ли уже стаи волков.

Сейчас за границей стоит заглушка `outside/scripted.js` с тремя соседями из `data/neighbours.js`: Род Ольхи (переселенцы), стойбище «Серых волков» (налёты), Дикие леса (звери). Налётчики не видят лагерь: угрозу они считают по последнему отчёту колонии, то есть по слухам суточной давности. Позже на место заглушки встанет статистическая карта мира с поставщиком той же формы, и локальная игра этого не заметит.

## Как добавить новое

**Ресурс.** Запись в `data/resources.js` с группой `group` (раздел на складе). Тег `fuel` пускает ресурс в костёр (порядок задаёт `burn`), `smelt` — в плавильню и кузницу, `ore` с полем `ore` — в добычу на руднике, `luxury` с `value` — в товары для будущей торговли. Склад, панель и грабёж подхватят ресурс автоматически.

**Еда.** Запись в `data/foods.js`: сытность, скорость порчи `spoil`, вкус `taste` (вкусное чаще становится любимым). Еда сама попадает в ресурсы с тегом `food`. У каждого поселенца есть любимая и нелюбимая еда: любимую он берёт первой, нелюбимую ест только когда больше нечего, и то и другое оставляет мысль в дневнике. Работа, которая приносит еду, указывает её полем `food`: такую работу колония хочет тем сильнее, чем сытнее эта еда (мясо и рыба сытнее ягод) и чем больше жителей по ней скучает, когда её запас кончился; сам поселенец охотнее берётся за работу, которая приносит его любимую еду.

**Работа.** Запись в `data/jobs.js` с одним из исполнителей:
- `harvest`: идти по полю `nav`, работать `time` тиков, взять единицу, унести `carry` единиц. Нужны `valid(w, i)` и `take(w, i)`. Если цель новая, добавьте поле в `navmaps.js`.
- `hunt`: выслеживать добычу из `prey` и стрелять с дистанции `range`.
- `build`: работать на стройке.

С `preferable: true` работа попадает в пул, из которого поселенцам выпадают любимая и нелюбимая работа. `requires: 'quarry'` открывает работу только после постройки. `desire(w, ctx)` задаёт, насколько колонии нужна эта работа сейчас.

**Предмет.** Запись в `data/items.js`: слот, число рук, `melee`, `ranged`, `block`, `armor`, `warmth`, `tool`, `dur`. Поселенцы сами оценят предмет и наденут его, если он им выгоден. Если у вещи есть особый значок в руке, добавьте его в `GLYPHS` в `render/looks.js`. Чтобы предмет можно было делать, добавьте рецепт.

**Руда.** Запись в `data/ores.js` (код в сетке, какой ресурс даёт, цвет, как лежат жилы: пласты `seam` или гнёзда `pocket`) и ресурс для неё в `data/resources.js` с `target` — сколько держать на складе. Рудник, слой ресурсов, подкраска скал, карточка клетки и легенда подхватят её сами.

**Украшение.** Запись в `data/luxury.js`: сколько самоцветов, во что оправлен (`setting`), работа, цена `value`. Из записи сами получаются ресурс склада и рецепт ювелира.

**Рецепт.** Запись в `data/recipes.js`: мастерская `at`, стоимость, работа, результат (`item` или `resource`), нужные постройки, `fuel` (сколько угля берёт горн) и функция `want(ctx)`: насколько колонии сейчас нужна эта вещь. Новая мастерская — это постройка с `station: true` и работа `{runner: 'craft', stations: ['id'], desire: atStations(0.5)}`: работа откроется, как только мастерская построена, и будет нужна, пока там есть заказ. Поле течения к мастерской создаётся само.

**Черта характера.** Запись в `data/traits.js` с множителями `mods`: `bravery`, `cold`, `hunger`, `speed`, `work`. Черты из одной группы `group` взаимоисключающие.

**Потребность.** Запись в `data/needs.js` (убывание, вред, задача, срочность) и имя потребности в `needs` у вида. Задачу, которая её утоляет, нужно добавить в `agents/tasks.js`.

**Существо.** Запись в `data/species.js`: здоровье, скорость, потребности, внешний вид `look`, мозг `brain`, добыча `yields`. Если нужна новая форма, добавьте её рисовальщик в `render/looks.js`. Если нужно новое поведение, добавьте мозг в `agents/brains/` и зарегистрируйте его в `brains/index.js`. Пример — волки: запись `wolf` в `species.js` с блоком `predator` (добыча, жертвы, рывок, выносливость, боязнь лагеря), фракция `predators`, мозг `brains/predator.js`, рисовальщик `wolf` в `looks.js` и миграция `wolves`. Остальные системы волков не знают. Фэнтезийная раса — это вид с `sentient: true` и своей фракцией.

**Фракция.** Запись в `data/factions.js`: цвет, мозг по умолчанию, список врагов.

**Постройка.** Запись в `data/buildings.js`: цена, работа, эффекты (`add`, `mul`, `yield.<ресурс>`, `jobSpeed.<работа>`) и `motive`, доводы для совета. Для особого эффекта при достройке есть `onFinish`: функция или имя хука в `settlement/buildings.js`.

**Миграция.** Две записи. В `data/migrations.js` — как выглядит группа (вид, фракция, снаряжение, сообщение) и `accept`: сколько из предложенных примет колония. В `outside/scripted.js` — поток: от какого соседа, когда первая проверка, сколько выходит в путь, когда следующая.

**Показатель для балансного прогона.** Строка в `data/metrics.js`: `id`, подпись, группа, число знаков и `get(w)`.

**Действие игрока.** Функция в `COMMANDS` (`commands.js`), а в оболочке кнопка, которая её вызывает.

## Механики

**Руда, железо и украшения.** В скалах лежат жилы железной руды, каменного угля и самоцветов (слой «Ресурсы» и подкраска скал на слое «Мир»). Цепочка:
- рудник открывает работу «добывать руду»: копают ту руду, которой на складе меньше нужного; выработанная жила оставляет проход, и за ним открывается новый склон;
- углежогная яма: 4 древесины → 3 древесного угля. Уголь — топливо горна, а костёр на нём горит дольше (сначала костёр жжёт дрова);
- плавильня: 2 железной руды + 1 уголь → слиток железа;
- кузница: меч, копьё с железным наконечником, железный топор, ламеллярный доспех. Другой железной брони нет;
- ювелирная мастерская: самоцвет + кость, дерево, камень или железо → бусы, шкатулки, идолы, гривны. Украшения копятся для торговли.

**Карта.** Колесо мыши приближает к курсору, перетаскивание левой (или любой) кнопкой двигает карту, кнопки «+», «−» и «Вписать» в углу карты делают то же с клавиатуры: `+`, `−`, `0`. Ближе всего клетка становится 40 точек экрана. Щелчок без перетаскивания — действие инструмента.

**Экран игры.** Над картой — время, инструменты, слои с фильтрами, скорость, ветер и действия. Справа — вкладки: склад и работы, поселенцы, постройки, совет, журнал, мир. Под картой — клетка под курсором и выбранный объект: поселенец, зверь, постройка (с её заказами) или клетка (с рудой). Пояснения об устройстве симуляции — в стартовом меню.

**Совет у костра.** С 19:00 до 21:30 поселенцы собираются у огня. Каждый голосует за постройку, которая решила бы его трудности за день: холод, голод, недосып, пожар, бой, долгие походы, неудачную охоту. Учитывается и любимая работа. Если ресурсов хватает, стройку закладывают сразу, иначе колония копит.

**Характеры.** Любимая и нелюбимая работа выбираются из пула работ с `preferable: true`. К ним добавляется до двух черт характера. Навыки растут с практикой и ускоряют работу до 1,7 раза.

**Зайцы.** Пасутся на лугах, предпочитая сочные и подальше от края карты, объедают ягоды, ночью дремлют, убегают от людей и огня. Охотник подкрадывается (так его замечают позже) и стреляет. Промах спугивает зайца. Размножения нет: зайцы приходят из-за края карты, пока луга могут их прокормить, и сами иногда уходят.

**Волки.** Стая из 2–4 волков приходит, когда на карте достаточно зайцев. Всё решает голод. Сытый волк бродит со стаей, но не упустит зайца, который выскочит прямо перед ним. Голодный идёт по следу (по полю течения к добыче, в обход озёр и скал) и загоняет зайца вместе со стаей: заяц быстрее на рывке, волк выносливее. Добыча делится между всеми, кто рядом, поэтому большой стае нужно много зайцев. Чем сильнее голод, тем смелее волк: подходит ближе к поселению, бросается на одинокого поселенца (ночью раньше), а изголодавшись — и на пару людей, и отступает неохотнее. Человек кормит стаю надолго. Оголодавшая стая без добычи может уйти искать другие угодья. Если волку не добраться до цели (вода между ними), он её бросает. Смелые поселенцы отбиваются, остальные бегут к лагерю, а соседи приходят на помощь. Как только рядом с жертвой двое и больше, стая отступает и какое-то время не пробует снова. Волки обходят освещённый лагерь, огонь и группы людей, а раненые или голодные уходят с карты. Пережитое нападение поселенцы вспоминают на совете и голосуют за частокол.

**Рыбалка.** При генерации мира вода делится на озёра. В озере не меньше 40 клеток живёт рыба: 0,3 рыбы на клетку, но не больше 90. Это конечный запас. Хижина рыбака (16 древесины) строится на берегу ближайшего рыбного озера, если такой участок есть в пределах 24 клеток от лагеря. В ней делают удочки с деревянным крючком (двуручные, работают и со спины), а ловля в ней на треть быстрее и улов на 30% больше. Рыбак садится на берег озера с рыбой и ловит по одной. Рыбу можно выловить до последней. Тогда озеро «отдыхает»: рыба возвращается сама (логистический рост плюс понемногу заплывающая извне), и ловить там снова начинают, когда озеро заполнится наполовину. На это уходит около двух недель. Рыба — еда (сытнее ягод, портится быстрее), коптильня перерабатывает и её. Сколько рыбы в каждом озере, видно при наведении на воду, на панели склада и на слое ресурсов. Параметры лежат в `world/lakes.js`.

**Снаряжение.** У каждого гуманоида четыре слота: левая рука, правая рука, тело и спина. Одноручная вещь занимает одну руку, двуручная (посох, молот, лук, праща) — обе сразу. На спине носят одну любую вещь: колчан со стрелами, заплечный короб (+2 к переноске) или запасной инструмент, который помогает в работе. Всё сделано из дерева, кости, шкур и кожи.

| Вещь | Руки | Что даёт |
|---|---|---|
| Дубина | 1 | удар ×1,3 |
| Копьё с костяным наконечником | 1 | удар ×1,55 |
| Топор с костяным клином | 1 | удар ×1,3, рубка ×1,6 |
| Щит из жердей и шкуры | 1 | блок 32% ударов в ближнем бою |
| Посох | 2 | удар ×1,1, блок 15%, ходьба +5% |
| Деревянный молот | 2 | удар ×1,9, стройка ×1,45, камень ×1,35 |
| Удочка с деревянным крючком | 2 | нужна для рыбалки, ловля ×1,6 |
| Лук | 2 | выстрел ×1,7 на 7 клеток, нужны стрелы в колчане |
| Праща | 2 | выстрел ×0,6 на 4,5 клетки, камни есть везде; с каменоломней ×1,6 |
| Одежда из лубяной ткани | тело | броня 8%, тепло 35% |
| Кожаная куртка | тело | броня 20%, тепло 55% |
| Кожа с костяными пластинами | тело | броня 35%, тепло 45%, ходьба −5% |

Вещи изнашиваются: оружие при ударах и выстрелах, инструменты в работе, броня при попаданиях, щит при блоке. Сломанная вещь пропадает. Поселенцы сами выбирают снаряжение со склада, когда проходят через лагерь: смелым важнее оружие и броня, охотникам — лук или праща, любителям рубки — топор, мерзлявым — тёплая одежда. Там же они пополняют колчан стрелами.

**Личность.** У каждого поселенца есть пол, характер, дневник и настроение. События дня становятся мыслями в дневнике: поел после голода, замёрз, выспался в шалаше, с удовольствием взялся за любимое дело или нехотя за нелюбимое, сделал вещь, положил последнее бревно, подстрелил зайца, бежал от пожара, на него напали волки, погиб товарищ, на совете его поддержали или нет. У каждой мысли есть вес, и со временем она остывает. Из свежих мыслей и неутолённых потребностей складывается настроение, которое на ±10% меняет скорость работы. Щелчок по поселенцу открывает под картой карточку: что он делает и где, что у него на душе, характер, самочувствие, чего он хочет (поесть, оружие, тёплую одежду, какую постройку), снаряжение, навыки и дневник по дням. Новая мысль — это запись в `data/thoughts.js` и вызов `think(w, agent, id)` там, где происходит событие.

**Журнал.** У каждой записи есть рубрика и уровень. Красный (тревога) — налёты, нападения, смерти, сгоревшие постройки. Жёлтый (важное) — стройка, новые поселенцы, решения совета. Зелёный (прочее) — ремесло, звери, погода. Над журналом есть переключатели уровней и рубрик, например можно скрыть ремесло. Фильтр влияет только на отображение и запоминается в браузере. Новая рубрика — это запись в `data/logTopics.js` и её имя в вызове `log`.

**Рост колонии и налёты.** Поселенцы приходят по одному, и чем больше колония, тем дольше ждать следующего: при 8 жителях и меньше — день, при 9 — два дня, при 10 — три, и так далее. Кроме того, нужны запас еды и свободные места: без шалашей лагерь вмещает 8 человек. Если срок подошёл, а прийти некуда, панель показывает причину ожидания. Сила налёта задаётся угрозой (`settlement/threat.js`). Угроза растёт со временем и с каждым прошедшим налётом, а ещё с тем, насколько колония «обросла жиром»: числом жителей, вооружённых и общей бронёй. О колонии налётчики знают по слухам: по ежедневному отчёту колонии, поэтому угроза меняется раз в день. Стойбище «Серых волков» стоит в 6 днях пути при редких набегах и в 3 днях при частых; банда выходит примерно раз в половину этого срока. От угрозы зависят размер банды (от 2 до 16), снаряжение, здоровье и меткость налётчиков, а каждый налёт немного приближает следующий. Колония, которая перестала расти, к третьей неделе встречает банды по 10 человек и больше. Ожидание поселенца, угроза, размер следующей банды, время до неё и соседи с расстоянием видны на панели склада.

**Скорость и производительность.** Скорости 1×, 2×, 4× и 8×; при 1× идёт 20 тиков в секунду. Панель «Расчёт за тик» показывает фактическую скорость рядом с выбранной: если компьютер не успевает, цифры разойдутся. Поля навигации больше не пересчитываются по кругу без нужды. Поле, помеченное изменённым, пересчитывается не чаще раза в 24 тика, чистое — раз в 600 тиков, а во время пожара раз в 24, потому что огонь и дым меняют цену пути. Поля, которые следят за движущимися целями (дичь, огонь), обновляются чаще. На средней карте тик стоит около 0,8 мс вместо 3,2 мс, поэтому 8× идёт без потерь.

**Конец игры.** Если в поселении никого не осталось или остался один человек, а лагерь в руках налётчиков или только что разграблен, игра останавливается и показывает летопись поселения: сколько оно продержалось и сколько людей через него прошло, что построили и сделали, сколько налётов пережили. Дальше идут номинации («Опора поселения», лучший охотник, лесоруб, собиратель, каменотёс, мастер, строитель, защитник, долгожитель, живучий, душа компании, вечно недовольный), интересные факты (первая потеря, самый большой налёт, любимая постройка совета, что чаще мастерили, кто держался последним) и список всех, кто здесь жил, с их судьбой и делами. Кнопка возвращает в главное меню. Счётчики для летописи собирает `settlement/chronicle.js`, итог строит чистая функция `settlement/summary.js`.

**Тревога.** Пока на карте есть налётчики, поселенцы бросают работу и собираются у костра, чтобы встретить врага вместе внутри зоны поселения. Тяжелораненые отходят в зону. Снаряжение налётчиков зависит от дня: первые банды приходят с дубинами и пращами в тряпье, поздние — с копьями, щитами, луками и в коже.

**Ремесло.** В хижине ремесленника делают одежду, оружие, инструменты, колчаны, короба и стрелы. Мастерская сама выбирает, чего колонии сейчас больше всего не хватает: одежды на всех, оружия на всех, лука для любителей охоты, стрел для лучников. Материалы, на которые совет копит, она не трогает. В дубильне шкуры выделывают в кожу. У каждой мастерской один верстак, поэтому за ним работает один мастер. Примерные сроки для обычного мастера: оружие или инструмент — полдня, броня — около дня, колчан или короб — треть дня, шкура или пять стрел — час-два. Кости и шкуры дают зайцы, а также волки, убитые в бою. Убитые налётчики оставляют снаряжение колонии как трофеи.

**Зона поселения.** Вокруг лагеря (8 клеток) и каждой постройки (5 клеток, у сторожевой вышки 11) лежат круги, которые сливаются в одну зону. В ней поселенцы бьют сильнее, частокол защищает их, волки не охотятся и держатся на расстоянии (ночью дальше), а человек внутри зоны не считается одиноким. При нападении поселенцы бегут к ближайшей точке зоны.

**Движение.** К общим целям (лагерь, ягоды, лес, добыча, край карты) существа идут по полям течения. К своей цели (зайцу, волку, налётчику, точке пастбища или маршрута) они идут по прямой, пока путь свободен, а когда мешает вода или скала — по пути A*, который пересчитывается, если цель сместилась. У угла препятствия существо скользит вдоль него. Если цель недостижима или существо долго не сдвигается с места, мозг получает отказ и выбирает другую цель.

**Слой ресурсов.** Под переключателем слоёв появляются фильтры по ресурсам, которые видны на карте: ягоды, древесина, камень. Их можно включать и выключать по отдельности. Ресурс попадает в фильтр, если в `data/resources.js` у него есть `map` и `mapColor`.

**Пожары и погода.** Влажная земля загорается хуже и сама гасит пламя. Дождь тушит огонь, а большой пожар делает дождь вероятнее.
