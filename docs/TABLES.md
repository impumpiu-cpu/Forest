## Справочники и схемы

Данные игры лежат в `src/data/*.js` вместе с комментариями; системы только читают их. Таблицы — **слой описания поверх кода**: схема ничего не копирует, а читает строки из исходных модулей и говорит, что значит каждый столбец.

- `src/data/schema/index.js` — список `TABLES` и группы `GROUPS`.
- `src/data/schema/columns.js` — что такое схема и столбец, типы, проверка значения (`valueErrors`, `checkTables`), что правится (`editable`), таблицы параметров (`paramRows`, `paramGroups`, `params`).
- `src/data/schema/auto.js` — таблицы, собранные из самих строк: `autoTable` для реестра или списка строк одного вида (работы, рецепты, мысли…), `objectTable` для объекта строк.
- `src/data/schema/sheets.js` — итоговые таблицы, которые считаются из других: «Существа (итог)», «Рецепты (итог)», «Постройки (итог)».
- `src/data/schema/layer.js` — слой правок как данные и отметка мира.
- `src/data/schema/edits.js` — запись, проверка и сброс правок.

**Одна сущность — одна строка**, даже если её числа лежат в разных файлах: строка «Расы» — это `races.js` + её строка `balance/creatures.js` + её народ на карте мира из `peoples.js`.

Схема: `{id, label, group, note, key, rows(), columns, computed?, target?, after?, rowCheck?}`. `key` — столбец, который называет строку (уникален в таблице); `rows()` — строки; `computed` — вся таблица вычисляется; `target(row, column)` говорит, куда на самом деле писать значение, если строка — копия; `after()` пересобирает то, что сделано из таблицы при загрузке (предметы из форм и материалов).

## Группы таблиц

Таблиц больше сотни, в восьми группах. Точное число таблиц, строк и столбцов печатает `npm run tables`.

| Группа | Что в ней (примеры) |
|---|---|
| Словари | модификаторы существа и поселения, теги, типы урона, свойства оружия, лестница сложности, степени успеха, таблицы случайностей |
| Существа | расы, подрасы, монстры и звери (с поведениями пешки и нравами логов и держав), поведения, дела мира, имена, ценности, SPECIAL, кривые, состояния, урон по видам, места попадания, недуги, чувства, итоговые «SPECIAL (итог)» и «Существа (итог)» |
| Отношения | расы ↔ расы, мнение внутри группы, мировоззрение, державы ↔ державы |
| Вещи | материалы, формы, породы деревьев, камень, материалы рас, качество, клеймо кузнеца, цены, бой и сила, «Предметы (итог)» |
| Народы | народы мира, постройки городов (одна истина: расы, нужное в державе, потоки, металлы), блага городов, держава (показатели, разруха, указы, двор, события, правила), языки |
| Караван | постройки обоза, транспорт, правила похода, город и рынок, дорога и стоянки, рынок по ступени города, слава, темп похода |
| Поселение | жизнь поселения, повадки существ, природа карты, работы, рецепты, нужды, мысли, черты, навыки, мастера, еда, постройки, ресурсы, итоговые «Рецепты (итог)» и «Постройки (итог)» |
| Мир | биомы, логова и их правила, катаклизмы, жизнь логов и городов, правила бедствий, история мира, создание земли, почвы, плиты, породы, руды, ветры, влажность |

Таблицы параметров («Правила логов», «Жизнь поселения», «Правила похода» и подобные) — это наборы чисел из `src/data/` строками «параметр — значение»; подпись таблицы говорит, из каких файлов и объектов они взяты.

## Столбцы

Столбец: `{key, label, type, note?, min?, max?, ref?, values?, computed?, edit?, nullable?}`. `key` — путь в строке (`attack.power`, `align.order`).

| Тип | Значение |
|---|---|
| `text`, `num`, `int`, `bool` | строка, число, целое, да/нет |
| `enum` | слово из списка `values` |
| `ref` | один id таблицы `ref` (или реестра, набора) |
| `ids` | список id |
| `map` | набор «ключ → число» (ключи из `ref`, числа в пределах `min…max`) или «ключ → слово» |
| `special` | пределы SPECIAL `{S: [lo, hi], …}` |
| `shift` | сдвиг SPECIAL `{S: +1, …}` |
| `color`, `formula`, `list` | цвет, функция (показывается её код), список объектов словами — только для чтения |
| `json` | значение смешанного вида |

`computed` у столбца — значение считает игра (например, поправка КС, подобранная ареной). `check(v)` — дополнительная проверка, которую тип выразить не может (объект `effects` против словаря). Пределы осей мировоззрения берутся из `AXIS_MAX` (`data/values.js`).

## Экран таблиц

`forest.html` → «⚙ Настройки» (`forest.html#settings`), код — `src/app/tablesView.js`.

- Слева — список таблиц по группам с числом строк; на телефоне он уходит наверх. Таблицы с правками отмечены.
- Таблица: заголовок и первый столбец закреплены; под названием столбца — его ключ. Наведите на заголовок — подсказка: что это, пределы, вычисляется ли.
- Щелчок по заголовку — сортировка: по возрастанию → по убыванию → как в файле.
- Фильтр по строкам ищет по тексту всех ячеек.
- Вычисляемое — курсивом.
- Внизу — строка проверки: «все значения в пределах, ссылки сходятся» или список несоответствий.
- Последняя открытая таблица запоминается в браузере.

## Правки таблиц

Правки — **только для экспериментов**: исходники не меняются, без слоя правок игра такая, как написано в коде.

**Как устроено.** Правка пишет значение прямо в определение, которое читает игра (вид, материал, строку матрицы отношений, параметр), а число кода запоминает; сброс возвращает его. Где лежит значение у строк-копий, говорит `target` схемы. После правки «Форм» и «Материалов» предметы пересобираются; кэши, сделанные из таблиц (рейтинг силы, копии одного справочника в другом), слушают правки через `onEdit` (`schema/layer.js`) и считаются заново.

**Что не правится:** вычисляемые таблицы и столбцы, ключ строки, столбцы типа `formula`, `list`, `color`, столбцы, закрытые схемой (`edit: false` — значение принадлежит другой таблице), и постоянные числа кода в таблицах параметров (видны, но не правятся). Значение, которое один справочник берёт из другого через геттер, правится там, откуда взято.

**Проверка при вводе.** Значение проверяется по столбцу (пределы, существующие id, слова из списка); у `json` должен остаться тот же вид значения; пустое не принимается там, где в коде есть значение (кроме столбцов `nullable`); список чисел сохраняет длину. Таблица может проверить всю строку после записи (`rowCheck`) и отказать. Неверное не записывается, причина видна под панелью. Значение, равное числу кода, — не правка.

**Экран.** Над таблицей — панель:
- «Правка: вкл/выкл» — в режиме правки правимое подчёркнуто;
- счётчик правок и список всех правок «было → стало» со ссылкой на таблицу и ↺ у каждой;
- «Выгрузить правки» — файл `forest-tables.json`;
- «Загрузить правки…» — правки из файла заменяют нынешние;
- «Сбросить таблицу», «Сбросить всё».

Щелчок по ячейке открывает поле: число; да/нет переключается щелчком; выбор из списка для слов и ссылок; строка для наборов («forest 1, meadow 0.5»), пределов SPECIAL («S 1-10, P 3-11»), сдвигов («S +1, I -1») и списков («id, id»). Enter или уход с поля — записать, Esc — отменить. Правленая ячейка — в рамке, с подсказкой «в коде: …» и ↺.

**Хранение.** Слой правок хранится в браузере (`localStorage`, ключ `forest.tables`) и применяется при загрузке страницы: `src/ui/tableEdits.js` подключается первым в `forest.html`, поэтому правки уже на месте, когда загружаются системы и делается игра или мир. То, что из сохранённого слоя не применилось (таблицы или строки больше нет), показывается на экране таблиц. Счётчик правок виден в шапке меню.

Правки действуют только в браузере. Балансные прогоны, арена и проверки (`npm run balance`, `npm run arena`, `npm test`) идут по числам кода.

## Мир и игра помнят правки

Новый мир (`a.tables`, `atlas/generate.js`) и новое поселение (`w.tables`, `sim.js`) получают отметку: подпись слоя, число правок и сам слой (`editsStamp`). Мир без правок — без отметки. Отметка сохраняется вместе с ними и входит в хеш мира.

Мир или игра, созданные под другими правками, при открытии предупреждают плашкой сверху и в строке статуса (`stampWarning`): например, «Мир создан с правками таблиц (6 правок), а сейчас правок нет: дальше всё идёт по исходным числам». В списках библиотеки у таких миров — «с правками таблиц (N)».

## Конструктор существ

Главное меню → **Конструктор существ** (`forest.html#bestiary`, `src/app/beastView.js`): один вид — одна форма. Слева виды по родам (звери, чудовища, нечисть, нежить, демоны) с поиском; справа облик, нарисованный как на карте (`render/looks.js`), и разделы:

| Раздел | Откуда поля |
|---|---|
| Имя и облик | «Монстры и звери»: название, падежи, род, разум, облик (`look.shape` из списка рисовальщиков), размер, цвет |
| Теги | все теги вида из `data/tags.js` (разумный, крупный, ночной, зимняя спячка…), где бы ни лежал их столбец |
| Тело | строка `data/balance/creatures.js`: пределы SPECIAL, здоровье, скорость, удар; КС-поправку считает арена |
| Поведение | список поведений ([Поведение](BEHAVIOUR.md)) по полосам: галочка включает, ▲▼ меняют порядок, готовые списки `WAYS` — одним выбором; серое — поведение читает блок, которого у вида нет (под ним сказано какой) |
| Нравы на карте мира | список дел логов этого вида и их главарей (`deeds.lair`, [Мир → Нравы](WORLD.md#нравы-дела-логов-и-держав)) по полосам, как поведение: галочка, ▲▼, готовые списки `DEED_WAYS` (`lair`, `captors`, `dragon`); раздел есть у видов, которые живут логовами (род логова — таблица «Логова»); нравы держав (`deeds.realm`) — в таблице «Расы» |
| Потребности, жар и приход; числа повадок; добыча и приручение | «Повадки видов»: `needs`, `arrive`, блоки `predator`, `flee`, `grazes`, `mule`, `vermin`, `spirit`, `tame`, добыча |
| Клички | «Клички и прозвища» для приручаемых |

Каждое поле — ячейка таблицы и пишется через тот же слой правок, сразу: оно живёт в этом браузере, входит в файл правок и действует в каждой новой игре и мире; ↺ возвращает число кода.

**Новый вид** — копия открытого под новым латинским id (`data/species.js cloneSpecies`): вместе со строкой тела; он помечен «новый» и хранится в слое правок (псевдотаблица `newSpecies`: откуда скопирован и как назван), при каждом запуске делается заново перед правками его ячеек и убирается кнопкой «Убрать вид» или из списка правок в «Настройках». Приход на карту (`data/migrations.js`, `outside/scripted.js`, сосед `data/neighbours.js`) собирается из блока `arrive`, и для нового вида тоже: вид без `arrive` сам не приходит (олень и волк приходят по пресетам полигона, их копия — нет); дайте копии `arrive.group`, `arrive.every`, `arrive.cap`, `arrive.chance`, `arrive.first` — и она пойдёт, откуда идёт основа. Сохранение с новым видом открывается, пока вид есть в правках; «Монстры и звери» и остальные таблицы показывают его как обычную строку.

## Выгрузка

Кнопки «CSV» и «JSON» над таблицей выгружают **то, что показано** — с фильтром и сортировкой.

- `<id>.csv` — разделитель `;`, в начале BOM: Excel в русской локали открывает его сразу таблицей. Первая строка — названия столбцов, вторая — ключи. Числа и слова как есть, остальное — JSON, функции — их кодом, бесконечность — `Infinity`.
- `<id>.json` — массив строк `{ключ столбца: значение}`.

## Проверка таблиц

`npm run tables` (`tools/check-tables.mjs`, входит в `npm test`):
- каждое значение по своему столбцу: пределы, существующие id, слова из списка, уникальные ключи;
- у каждой таблицы группа есть в `GROUPS` (иначе её не видно на экране), id таблиц не повторяются;
- правки: значение доходит до вида, матрицы и предметов; неверное, вычисляемое и постоянное отклоняются; мир с правками несёт их и меняет хеш, без правок — нет; сброс возвращает числа кода; слой применяется заново;
- имена: у каждой расы мужские и женские, у приручаемых — клички, конструктор имён работает;
- кривые конечны и при норме дают множитель 1; словари модификаторов и тегов сходятся; итоговые таблицы конечны и следуют за правками (печатает рецепты в убыток);
- защита правки: набор заведомо недопустимых правок отклоняется.

Ссылки между самими справочниками (ресурсы в рецептах, постройки в `needs` и так далее) проверяет `tools/check-data.mjs` — [Проверки](TESTING.md#проверка-справочников).

## Новая таблица

Одна запись в `TABLES` (`src/data/schema/index.js`): источник `rows()`, ключ, столбцы. `ref` у столбцов сразу дают проверку ссылок. Для реестра или списка строк одного вида хватит `autoTable`, для набора параметров — `params(() => paramRows(OBJ))` или `paramGroups({...})`. Группа должна быть из `GROUPS`.
