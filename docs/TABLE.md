# Таблицы, мировоззрение, главари и новое меню

Рабочий документ ветки `Table`. Цель ветки — навести порядок в структуре данных и в запуске, заложить основу для асимметрии рас (следующая большая задача). Первый круг вопросов закрыт: решения записаны в каждом разделе, план этапов — в конце. **Работа начинается по команде.**

Условные обозначения: ✅ есть в коде · 🟡 есть частично · ⬜ нет.

## 1. Репозиторий как база данных

### Что есть сейчас

Почти всё, что описывает мир, лежит в справочниках `src/data/*.js` (≈60 файлов), а системы только читают их. Но справочники неоднородны: `Registry` с id, обычные массивы, матрицы (`relations.js`), наборы констант (`DIPLOMACY`, `OPINION`), строки с функциями (`name: m => …`). Сведения об одной сущности разнесены по файлам: раса — это `races.js` + `balance/creatures.js` + `peoples.js` + строка в `relations.js`.

### Решения

- **Слой описания поверх кода**, данные остаются в `.js` вместе с комментариями. Перенос в JSON/SQLite — не сейчас.
- **Схемы таблиц** — `src/data/schema/`: для каждой таблицы источник, ключ, столбцы с типом и границами, ссылки на другие таблицы, вычисляемые (только для чтения) столбцы. Строки с функциями показываются как «формула» и не правятся.
- **Экран «Настройки → Таблицы»** строится по схемам: список таблиц, таблица, сортировка, фильтр, подсказка столбца.
- **Правки — только для экспериментов**: слой `overrides` хранится в браузере и выгружается файлом; «запекания» в исходники нет. Слой входит в сохранение мира и в его хеш: мир, сотворённый с правками, без них загрузится с предупреждением.
- **Одна сущность — одна строка на экране**, файлы остаются раздельными: «Раса» = `races.js` + `creatures.js` + народ из `peoples.js`.
- Выгрузка любой таблицы в CSV/JSON.
- `npm run check-data` берёт границы и ссылки из схем.

## 2. Оружие: форма × материал × качество + клеймо

### Что есть сейчас

Предмет = форма (`forms.js`) × материал (`materials.js`) × качество (`quality.js`, +0…+4). У формы есть тип удара (`blow`: колющий / рубящий / дробящий) и защита по типам (`vs`).

### Решения: клеймо мастера

Таблица `data/balance/marks.js`. Клеймо — свойство народа-кузнеца, а не формы.

| Клеймо | Народ | Свой тип |
|---|---|---|
| Эльфийская работа | эльфы | колющий |
| Орочья работа | орки | рубящий |
| Гномья работа | гномы | дробящий |
| — | люди | нет: середняк, ни бонусов, ни штрафов |

- **Бонус крупный** (черновик: +25%), сильнее одной ступени качества (+15%). Действует **только на свой тип**: урон этого типа и защита от этого типа.
- **Одно клеймо на вещь**, двух не бывает.
- **«Чужая» форма сохраняет свою природу и получает долю своего типа.** Гномий меч — по-прежнему меч (рубящий), но в его ударе появляется дробящая часть, и она усилена клеймом: «заточенный лом не перестаёт дробить». Технически: удар клеймёной вещи делится на тип формы и тип клейма (черновик: 70 / 30; для формы своего типа — 100% и полный бонус). Защита (`vs`) клеймёной брони и щита растёт против типа клейма.
- **Клеймо ставится только при ковке в городе** народа-мастера (кузня города в кампании). Ни поселение, ни караван клейма не ставят, даже если в них есть кузнец этой расы. Купить у торговца или взять трофеем — можно.
- **Городская ковка — не ниже +1** (добротное и выше), чтобы ковать в городе было выгодно и с клеймом, и без него (у людей).
- Цена: множитель клейма поверх цены качества; `npm run items` и `npm run arena` учитывают клейма.

**Открыто (решим на этапе):** точные числа — бонус (25%?) и доля типа клейма в «чужой» форме (30%?); распределение качества городской ковки (+1 как правило, +2 — у хорошей кузни?).

## 3. Мировоззрение: компас ±5

### Что есть сейчас

Оси уже есть, но в шкале ±3 и без столиц (`data/values.js`): **порядок** (закон ↔ хаос) и **милосердие** (добро ↔ зло). Раса задаёт точку и разброс, пешка получает свою точку около неё; это влияет на мнение, помощь раненому, реакцию на продажу пленных.

### Решения

**Три слоя, всё обрезается по ±5:**
1. **Раса** — центр на компасе ±5.
2. **Столица (держава)** — при основании: раса + отклонение до ±3 по каждой оси. Каждый народ приходит двумя группами — значит две державы одной расы с разным характером.
3. **Пешка** — столица + отклонение до ±3. Без мира (полигон) роль столицы играет раса.

Отклонение — «колокол»: крайние значения редки, но возможны. **Белые вороны задуманы**: добрый народ может дать злую пешку, гном может быть хаотичным. Под них позже — свои механики отношений.

**Компас ползает со временем:**
- держава: долгая война, набеги, резня городов → к злу; долгий мир, торговля → к добру; распад и смены столицы → к хаосу; долгое правление одной столицы → к закону;
- пешка: спасли, перевязали, поделились → к добру; предательство, пытки, продажа пленных рядом → к злу; служба, присяга, порядок совета → к закону; побег, бунт, жизнь вне закона → к хаосу.
Скорость — малая, правила — в таблице сдвигов.

**Ярлык клетки на карточке** — девять клеток классического компаса, порог, например, |значение| ≥ 2:

| | **Хаотичный** (≤ −2) | **Нейтральный** | **Законопослушный** (≥ +2) |
|---|---|---|---|
| **Добрый** (≥ +2) | хаотичный добрый | нейтральный добрый | законопослушный добрый |
| **Нейтральный** | хаотичный нейтральный | истинно нейтральный | законопослушный нейтральный |
| **Злой** (≤ −2) | хаотичный злой | нейтральный злой | законопослушный злой |

Рядом остаются две оси числами.

**Расстановка рас** (решение по оркам: орда → −2 в хаос; остальное — текущее ×5/3, правь в таблице):

| Раса | Закон ↔ хаос | Добро ↔ зло | Ярлык |
|---|---|---|---|
| Гномы | +5 | 0 | законопослушный нейтральный |
| Тёмные эльфы | +3 | −3 | законопослушный злой |
| Полурослики | +2 | +3 | законопослушный добрый |
| Лесные эльфы | +2 | 0 | законопослушный нейтральный |
| Люди | 0 | 0 | истинно нейтральный (самый широкий разброс) |
| Орки | **−2** | −2 | хаотичный злой |
| Великаны | −2 | +2 | хаотичный добрый |
| Тролли | −2 | −2 | хаотичный злой |
| Гоблины | −3 | −2 | хаотичный злой |
| Огры | −3 | −3 | хаотичный злой |
| Гноллы | −2 | −5 | хаотичный злой |
| Некроманты | +2 | −5 | законопослушный злой |

**Где сказывается:**
- **державы**: стартовое отношение = память рас + близость на компасе; две державы одной расы при большом расхождении могут враждовать и раскалываться (`SCHISM` уже есть); злые охотнее идут в набег, законопослушные реже рвут мир;
- **внутри группы**: `OPINION` пересчитывается под ±5, кроме штрафа за разрыв появляется плюс за близость;
- **взаимопомощь**: перевязать чужака, поделиться едой, вступиться — пороги по оси добра; держать слово, слушаться совета и дозора — по оси закона.

## 4. Основа для асимметрии: постройки, расселение, технологии

### Решения

Полноценных «технологий» (изобретений, дерева) в этой ветке нет — это следующая стадия. Здесь закладываем основу таблицами:

- **Технологии — таблица-список**, `data/tech.js`: каждая строка просто включает уже существующие уровни материалов, формы, рецепты и постройки (`opens`).
  - **Доступность — по расе**: что раса вообще может знать (`races`).
  - **Открытие — по державе**: что конкретная держава уже знает (`a.realms[].tech`). Пока открытие — простое правило (эпоха, ступень городов); как держава к технологии приходит, решим в асимметрии.
- **Постройки станут расовыми**: в `townBuildings.js` поле `peoples` уже есть — в схеме таблицы делаем его видимым и правимым, чтобы потом развести постройки по расам.
- **Особенности расселения** (плотность: 60 тыс. гномов занимают меньше места, чем 15 тыс. эльфов или орков) — столбец в таблице народов, заполняем в асимметрии.
- **Бафы/дебафы рас за территорию** — формат таблицы раса × биом → эффекты; числа — в асимметрии.

**Караван — это караван.** Он ничего не изобретает: у него есть только база, остальное покупается в городах. Список того, что каравану доступно (постройки стоянки, рецепты), выносится в таблицы для экспериментов.

## 5. Новое меню и `Forest.bat`

### Решения

- Рядом со старым запуском — новый; **старый (`start.bat`, `index.html`) остаётся техническим полигоном**.
- `Forest.bat` — тот же сервер (`tools/serve.mjs`), открывает `forest.html`; новая оболочка — `src/app/`, ядро общее.
- **Мелькание старого блока** (`#explain` и старый текст `#worldInfo` в `index.html` видны до загрузки модулей) — исправляем в этой ветке.

**Главное меню** (названия пока такие):

**1. Создать землю** — только земля и климат, без народов и истории.
- Генерация: плиты, рельеф, море, температура, ветры, осадки, реки, биомы.
- **Инструменты первой версии — правка базы, а не результата**:
  - *терраморфинг*: сдвинуть плиты, поднять/опустить плиту или участок;
  - *климат*: температура полюсов и экватора (и, вероятно, влажность).
  После правки алгоритмы заново считают всё, что ниже по цепочке: залегание руд, реки, озёра, биомы.
- Сохранить землю — отдельный тип записи в библиотеке и файлом.

**2. Заселение мира** — загрузить землю и вести историю вручную. **Эпох нет.**
- Пользователь вносит «возмущение»: **Расы** (какие и где высадить), **Монстры** (кого и куда; ручное добавление логов), **Катаклизмы** (до трёх — основа эпика).
- Затем запускает время: **+5 · +10 · +25 · +50 · +100 лет**; смотрит результат, снова вмешивается или мотает дальше. Летопись сбоку.
- Тонкая настройка карты и правил — из таблиц.
- Сохранить мир с обитателями и летописью.

**3. Кампания** — загрузить живой мир, выбрать столицу, поход за артефактом, который остановит грядущий катаклизм. **Локальная карта (поселение) — только внутри кампании**, отдельной кнопки нет.

**4. Быстрый старт** — нынешняя «Эпическая кампания» одной кнопкой: **видимый случайный сид** (с кнопкой «случайный» и копированием) → земля → история → выбор столицы → поход.

**⚙ Настройки** — раздел **Таблицы** (раздел 1) и общие параметры (подробность летописи, скорость, автосохранение).

## 6. Главари логов (новое)

### Что есть сейчас

- Логово (`atlas/lairs.js`) — точка с хозяином-видом, силой и возрастом; в «диффузном» режиме оно кормится, растёт, плодит новые логова, дерётся с соседями и шлёт набеги.
- В 30 лет логово становится древним (`ANCIENT_YEARS = 30`, летопись: «о нём слагают страшные сказки»).
- У катаклизма есть босс: существо, выращенное за пределы своего вида (`agents/special.js` `bossSpecial`), его логово не падает, пока он жив, и он ведёт набеги.
- По карте уже ходят «отряды» (`atlas/parties.js`): набег из логова, выводок, армия державы, дракон в полёте — с путём, днями и отрисовкой.

### Предложение

**Главарь** — именной лидер древнего логова, который переводит логово из диффузного режима в дискретный.

- **Появление**: логово старше 30 лет (древнее) получает шанс в год родить главаря; один главарь на логово. Летопись: «В логове … поднялся главарь — …».
- **Статы**: как у босса катаклизма, но слабее — выращен за пределы своего вида на меньшую величину (`bossSpecial` с меньшим `add`/`cap`). Имя, мировоззрение, ценности — как у пешки. Главарь катаклизма остаётся ступенью выше.
- **Пешка на карте мира**: главарь — отряд в `parties`, его путь виден наравне с армиями держав (свой значок и цвет).
- **Думает и планирует**: у главаря есть цели, а не случайные набеги:
  - *набег* на слабый город поблизости (как сейчас, но цель выбирает он, по силе и добыче);
  - *расширение*: увести выводок и основать дочернее логово, которое ему подчиняется;
  - *война с соседним логовом* или *подчинение* слабого логова (растёт «владение» главаря);
  - *уход и смена логова*, если его теснят;
  - позже — *сделки*: только у видов с разумом (`mind: 'sentient'`), с державами по мировоззрению.
- **Смерть главаря**: убит в бою, армией державы, героем кампании — логово возвращается в диффузный режим и слабеет; летопись пишет, кто его убил.
- **Кампания**: главарь — именной противник по дороге, у него есть трофей; его логово можно найти по слухам в городах.

**Вопросы**
- 6.1. Главарь только у видов с разумом (`semi`, `sentient`) или и у зверей (вожак стаи волков, «старый медведь»)?
- 6.2. Сколько главарей одновременно на мир — без предела или потолок (например, не больше одного на 10 логов), чтобы карта не превратилась в муравейник?
- 6.3. Главарь стареет и умирает своей смертью, оставляя наследника, или живёт, пока его не убьют?
- 6.4. Может ли главарь стать боссом катаклизма (катаклизм выбирает самого сильного главаря), или босс всегда появляется отдельно?

## 7. План этапов

Каждый этап — `npm test` зелёный и раздел «Сделано» здесь.

1. **Каркас**: `Forest.bat`, `forest.html`, `src/app/` с экранами-заглушками и переходами; исправление мелькания в `index.html`; видимый сид в «Быстром старте» (он сразу работает — это нынешний эпик).
2. **Схемы таблиц + «Настройки → Таблицы» только для чтения**: расы (вместе с `creatures.js`, биомы расселения), монстры, отношения, материалы, формы, качество, народы, постройки, список каравана; проверка границ в `check-data`.
3. **Слой правок** для экспериментов: в браузере, файлом, в сохранении мира; предупреждение при загрузке.
