# Таблицы, мировоззрение и новое меню

Рабочий документ ветки `Table`. Цель ветки — навести порядок в структуре данных и в запуске до того, как браться за асимметрию рас. Пока это документ для обсуждения: в каждом разделе есть «что есть сейчас», «предложение» и «вопросы». Ответы на вопросы превращаются в решения, решения — в план этапов в конце.

Условные обозначения: ✅ есть в коде · 🟡 есть частично · ⬜ нет.

## 1. Репозиторий как база данных

### Что есть сейчас

Код уже построен вокруг справочников: почти всё, что описывает мир, лежит в `src/data/*.js` (≈60 файлов, ≈6 тыс. строк), а системы в `atlas/`, `agents/`, `settlement/`, `campaign/` только читают их. Но «таблицы» неоднородны:

- одни — `Registry` с id и полями (`FACTIONS`, `KINS`, `QUALITY`, `WORLD_PEOPLES`, `STATS`, `VALUES`);
- другие — обычные массивы или объекты (`RACES`, `MONSTERS`, `MATERIALS`, `FORMS`);
- третьи — матрицы (`relations.js`: строки и столбцы рас);
- четвёртые — наборы констант (`DIPLOMACY`, `OPINION`, `STRENGTH`);
- у части строк есть функции (`name: m => …` в `forms.js`, `EFFECTS` в `special.js`) — такие строки нельзя показать и править как таблицу.

Сведения об одной сущности разнесены по нескольким файлам. Например, раса: `races.js` (облик, дом, мировоззрение, ценности), `balance/creatures.js` (SPECIAL, тело, удар, КС), `peoples.js` (народ на карте мира), `relations.js` (строка в матрице), `diplomacy.js` (общие правила), `raids.js` (банды).

### Предложение

Не переписывать данные в другой формат, а добавить **слой описания таблиц**: `src/data/schema/`. Для каждой таблицы — короткое описание:

```js
// src/data/schema/races.js
export default {
  id: 'races', label: 'Расы', group: 'Существа', source: RACES,
  key: 'id',
  columns: [
    {key: 'label', label: 'Название', type: 'text'},
    {key: 'align.order', label: 'Закон ↔ хаос', type: 'number', min: -5, max: 5, step: 0.5},
    {key: 'align.mercy', label: 'Добро ↔ зло', type: 'number', min: -5, max: 5, step: 0.5},
    {key: 'home', label: 'Родные биомы', type: 'map', of: 'biomes', min: 0, max: 1},
    …
  ],
  computed: ['ks'],            // только для чтения: пересчитывается ареной
};
```

Что это даёт:

1. **Экран «Настройки → Таблицы»** строится по схемам автоматически: список таблиц слева, таблица справа, сортировка, фильтр, подсказка столбца из комментария.
2. **Правки — как слой поверх кода**, а не переписывание исходников: `overrides = {races: {elf: {'align.order': 2}}}`. Слой хранится в браузере и выгружается файлом. Сброс — удалить слой.
3. **Проверка** (`npm run check-data` уже есть) получает границы из схемы: значение вне `min…max` или ссылка на несуществующий id — ошибка.
4. **Детерминизм**: слой правок входит в сохранение мира и в его хеш. Мир, сотворённый с правками, без них не загрузится молча — будет предупреждение.
5. **Выгрузка в CSV/JSON** любой таблицы — для работы в Excel/Google Sheets и обратной загрузки.

Строки с функциями оставляем в коде, а в схеме помечаем столбец как «формула» (показывается, но не правится). Со временем формулы можно заменить параметрами.

## 2. Оружие: материал × тип × редкость + клеймо

### Что есть сейчас

Это уже работает именно так, как ты описал: предмет = **форма** (`forms.js`: копьё, меч, булава…) × **материал** (`materials.js`: кость, бронза, железо, мифрил…) × **качество** (`quality.js`: +0…+4, «обычное … эпическое»). Новая строка материала сразу даёт все формы из него. У каждой формы есть тип удара — колющий / рубящий / дробящий (`blow`) — и защита по типам (`vs`): кольчуга держит рубку и пропускает молот.

«Редкость» сейчас живёт в двух местах: у материала (`rarity` — множитель цены и «продаёт ли торговец») и у качества (`rank`). Это нормально, но на экране стоит показывать одной колонкой.

### Предложение: клеймо мастера

Новая таблица `data/balance/marks.js` — **клеймо**: свойство, которое накладывает только кузнец города определённого народа. Своё поселение клейма не ставит (если не решим иначе, вопрос 2.3).

| Клеймо | Народ | Удар | Защита | Примечание |
|---|---|---|---|---|
| Эльфийская работа | эльфы | колющий: урон ×1,10 | броня/щит против колющего ×1,10 | лёгкость: вес брони ×0,95? |
| Орочья работа | орки | рубящий: урон ×1,10 | против рубящего ×1,10 | |
| Гномья работа | гномы | дробящий: урон ×1,10 | против дробящего ×1,10 | прочность ×1,2? |
| — | люди | — | — | середняк, клейма нет |

Как устроено:
- клеймо хранится на экземпляре вещи, как качество: `{type: 'ironsword', q: 1, mark: 'orc'}`;
- урон по своему типу удара ×(1 + `hit`), защита от своего типа — к `vs` формы ×(1 + `guard`);
- оружие другого типа клеймо не усиливает (эльфийский молот = обычный молот с наценкой), либо такие сочетания кузнец вообще не делает — вопрос 2.2;
- цена: множитель как у ступени качества, с поправкой на расстояние до народа-мастера;
- где взять: кузня в городе народа (кампания, `campaign/town.js`), торговец из такого города, трофеи с воинов этого народа.

**Вопросы**
- 2.1. Величина бонуса: +10% к урону и защите своего типа — так? Или крупнее (+15–20%), чтобы клеймо было заметно рядом с качеством (+1 даёт +15% урона)?
- 2.2. Клеймо на «чужом» типе: запрещено, бесполезно или даёт что-то своё (например, прочность)?
- 2.3. Может ли эльф-кузнец в нашем поселении ставить эльфийское клеймо? Если нет — клеймо целиком «городское», и это даёт смысл торговле и походу.
- 2.4. Люди «середнячком» — совсем без клейма, или у них клеймо «на всё понемногу» (+3% ко всем трём)?

## 3. Мировоззрение: компас ±5

### Что есть сейчас

Компас уже есть, но в другой шкале и без столиц (`data/values.js`):
- ось **порядок** (−3 вольница … +3 порядок) — это закон ↔ хаос;
- ось **милосердие** (−3 жестокость … +3 милосердие) — это добро ↔ зло;
- у каждой расы есть точка по умолчанию и разброс (`races.js` `align: {order, mercy, spread}`);
- каждая пешка получает свою точку около расовой (`agents/special.js`), её видно на карточке;
- точка влияет на мнение (`relations.js`: разница милосердия ≥3 → −1, порядка ≥4 → −0,5), на помощь раненому (`together.js`), на реакцию на продажу пленных (`slavery.js`).

**У держав и столиц мировоззрения нет**: две державы одной расы сейчас мыслят одинаково.

### Предложение: три слоя

1. **Раса** — центр, ±5 по каждой оси (переводим текущие значения в новую шкалу, см. таблицу).
2. **Столица (держава)** — при основании получает точку = раса + отклонение не больше ±3 по каждой оси. Каждый народ приходит двумя группами (`arrive.groups: 2`), значит у каждой расы на старте две державы с разными характерами: например, «суровые» и «мягкие» гномы.
3. **Пешка** — точка = столица + отклонение не больше ±3. На локальной карте без мира (полигон) роль столицы играет раса.

Всё обрезается по ±5. Отклонение — не равномерное, а «колокол» (сумма трёх случайных), чтобы крайние значения были редки, но возможны.

Предварительная расстановка рас (текущее ×5/3, округлено; **правь смело** — это главный вопрос раздела):

| Раса | Закон ↔ хаос (сейчас → ±5) | Добро ↔ зло (сейчас → ±5) | Где на компасе |
|---|---|---|---|
| Гномы | +3 → **+5** | 0 → **0** | законопослушные, нейтральные |
| Тёмные эльфы | +2 → **+3** | −2 → **−3** | законопослушные злые |
| Полурослики | +1 → **+2** | +2 → **+3** | законопослушные добрые |
| Лесные эльфы | +1 → **+2** | 0 → **0** | ближе к закону, нейтральные |
| Орки | +1 → **+2** | −1 → **−2** | ближе к закону (орда), злые |
| Люди | 0 → **0** | 0 → **0** | истинно нейтральные, самый широкий разброс |
| Великаны | −1 → **−2** | +1 → **+2** | хаотичные добрые |
| Тролли | −1 → **−2** | −1 → **−2** | хаотичные злые |
| Гоблины | −2 → **−3** | −1 → **−2** | хаотичные злые |
| Огры | −2 → **−3** | −2 → **−3** | хаотичные злые |
| Гноллы | −1 → **−2** | −3 → **−5** | крайне злые |
| Некроманты (монстры) | +1 → **+2** | −3 → **−5** | законопослушные крайне злые |

Где сказывается:
- **отношения держав**: стартовое отношение двух держав = память рас + поправка за расстояние на компасе (близкие — теплее, далёкие — холоднее); две державы одной расы перестают быть «одним народом»: при большом расхождении между ними возможна вражда и раскол (`SCHISM` в `peoples.js` уже есть);
- **отношения внутри группы**: веса `mercyGap`/`orderGap` пересчитываются под новую шкалу; добавить «близость» (+) — сейчас есть только штраф за разрыв;
- **взаимопомощь**: кто перевязывает чужака, кто делится едой, кто вступается — пороги по оси добра; кто держит слово, подчиняется совету и дозору — по оси закона;
- **решения державы** (дальше): злые охотнее идут в набег, законопослушные реже рвут мир.

**Вопросы**
- 3.1. Расстановка рас в таблице — правь значения. Особенно орки: сейчас они «порядок +1» (орда с вождём). Оставляем или делаем хаотичными?
- 3.2. Отклонения ±3 + ±3 от расы дают пешку до ±6 от центра расы — значит гном может оказаться хаотичным. Так задумано (редкие «белые вороны») или пешку держим ближе (например, ±3 от столицы, но не дальше ±4 от расы)?
- 3.3. Ось сдвигается со временем? Например, держава после долгой войны сползает к злу, пешка после спасения — к добру. Или пока статично?
- 3.4. Нужен ли «ярлык» клетки компаса на карточке (законопослушный добрый и т.п.), или оставляем две оси числами со словами, как сейчас?

## 4. Расовые свойства и технологии

### Расовые бафы и дебафы за территорию (⬜)

Сейчас `home` говорит только, насколько биом подходит (сколько народа он прокормит). Предлагаю таблицу `data/balance/terrain-fx.js`: раса × биом → эффекты для пешки на локальной карте и для народа на карте мира:

| Раса | Биом | Эффект |
|---|---|---|
| Эльфы | лес | скрытность +, обзор +, сбор ×1,2 |
| Гномы | горы, предгорья | добыча ×1,3, холод ×0,8 |
| Орки | степь | скорость +, набеги дальше |
| Все | чужой биом (`home` < 0,2) | настроение −, скорость −5% |

Это и есть фундамент «асимметрии рас» — следующей большой задачи. Здесь только формат таблицы, сами числа — в той задаче.

### Технологии (⬜)

Сейчас «технологий» как сущности нет: что умеет народ, определяют постройки городов (`townBuildings.js`: `tier`, `requires`, `peoples`) и уровни материалов (`tier`: кость → бронза → железо → сталь «позже» → мифрил). Предлагаю отдельную таблицу `data/tech.js`:

| Поле | Смысл |
|---|---|
| `id`, `label`, `era` | название и эпоха, с которой доступна |
| `requires` | другие технологии |
| `peoples` | кому доступна (пусто — всем); `bonus` — кому дешевле |
| `opens` | что открывает: постройки городов, рецепты поселения, материалы и формы, клейма |
| `cost` | как народ к ней приходит на карте мира (годы, знание `lore` городов) |

Примеры: «бронзовое литьё» → бронза; «кузнечное дело» → железо; «сталь» → материал `steel`; «гномья ковка» (только гномы) → клеймо гномов и мифриловая кузня; «эльфийская тетива» → клеймо эльфов.

**Вопросы**
- 4.1. Технологии на карте мира — у народа, у державы или у города? Я предлагаю у державы: тогда две гномьи державы могут разойтись и по технике.
- 4.2. Поселение игрока получает технологии от своей столицы, изучает само, или и то и другое?
- 4.3. Делаем дерево технологий сразу или сначала таблицу-список, которая просто «переключает» уже существующие уровни материалов и постройки?

## 5. Новое меню и `Forest.bat`

### Что есть сейчас

`start.bat` → `index.html`: четыре карточки (Мир · Карта · Кампания · Эпическая кампания), всё в одном файле страницы и `src/main.js`.

**Мелькающее окно при запуске** найдено: это блок `<section id="explain">` в конце `index.html` (пять карточек «слой 1 · поля … что попробовать» — пояснения старого прототипа) и старый текст в шапке (`#worldInfo`, «Прототип локальной карты…»). У блока нет атрибута `hidden`, поэтому браузер рисует его, пока грузятся модули, а `main.js` прячет его уже потом. Исправление — одна строка (`hidden` у `#explain`); в новом меню этого блока не будет вовсе.

Случайный сид в эпике: поле `campEpicSeed` есть, и пустое поле даёт случайный сид, но сам сид нигде не показывается и кнопки «🎲» нет — повторить удачный мир нельзя. В «Быстром старте» сид будет видимым, с кнопкой «случайный» и копированием.

### Предложение

Рядом со старым запуском — новый, старый остаётся техническим полигоном:

- `Forest.bat` — тот же сервер (`tools/serve.mjs`), открывает `forest.html`;
- `forest.html` + `src/app/` — новое меню и экраны; ядро (`atlas/`, `world/`, `agents/`, `campaign/`) общее, меняется только оболочка;
- `start.bat` / `index.html` — без изменений, пока новые экраны не заменят старые; потом переименуем в «Полигон».

Главное меню:

**1. Создать землю** — только земля: плиты, рельеф, море, температура, ветры, осадки, реки, биомы (этапы `plates … rain` и гидрология из `atlas/stages.js`, без эпох).
- Инструменты доработки материка: поднять/опустить сушу кистью, сгладить, поставить горы, провести реку, сменить биом участка, пересчитать климат после правки.
- Сохранить землю (в библиотеку и файлом). Сохранение «земли» — отдельный тип записи, без народов и летописи.

**2. Заселение мира** — загрузить землю и вести историю вручную.
- Кнопки: **Монстры** (кого и куда; ручное добавление логов), **Катаклизмы** (до трёх — основа эпика; выбрать вид, эпоху, место), **Расы** (какие расы участвуют, где высадить группы, вручную).
- Промотка времени: **+5 · +10 · +25 · +50 · +100 лет**, пауза; летопись сбоку.
- Тонкая настройка: параметры эпох и дипломатии (из таблиц), видимые слои карты.
- Сохранить мир с обитателями и летописью (как сейчас «Мир»).

**3. Кампания** — загрузить живой мир, выбрать столицу, поход каравана за артефактом, который остановит грядущий катаклизм (связать квест с катаклизмом из шага 2).

**4. Быстрый старт** — нынешняя «Эпическая кампания» одной кнопкой: случайный (видимый) сид → земля → три эпохи → выбор столицы → поход.

**⚙ Настройки** — отдельный раздел:
- **Таблицы** — все справочники из раздела 1 для изучения и правки, с выгрузкой CSV/JSON и сбросом;
- общие параметры (язык летописи, подробность, скорость, автосохранение).

Карта «Карта» (локальное поселение) в новом меню пока не нужна отдельной кнопкой? Она остаётся в старом полигоне и в будущем станет частью кампании — вопрос 5.3.
