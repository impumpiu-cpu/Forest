## Где числа

Все числа, которые трогает балансировка, лежат в `src/data/balance/`, отдельно от названий, значков и логики:

| Файл | Что в нём |
|---|---|
| `weapons.js` | оружие: тир, форма, `melee {dmg, cd}`, `ranged {dmg, range, cd}`, блок, инструмент, прочность, цена |
| `armor.js` | щиты, одежда и броня: тир, форма, `armor`, `block`, `warmth`, `speed`, прочность, цена |
| `gear.js` | снасти и вещи для спины: удочка, колчан (сколько стрел), лоток, короб |
| `combat.js` | числа самого боя: базовый удар и выстрел, шанс попасть, вклад навыка, досягаемость, бонус дома, серебро, потолки качества, цена серебрения |
| `rules.js` | с чем сравнивают проверки: шаг PL, эталон, коридоры тиров, допуски цены, пороги арены. Игра этот файл не читает |
| `power.js` | формулы PL для проверок |

Строка в таблице находится по `id` предмета. В `data/items.js` осталось то, что вещь есть: название, слот, число рук, значок, цвет, из чего она (`iron`, `silver`), что покупная (`tradeOnly`), чем стреляет. Предмет без строки в таблицах игра не загрузит; строку без предмета поймает `npm test`.

Цены качества +1…+4 и шансы мастера живут в `data/quality.js`, цены сырья — в `data/resources.js`, критический удар и смертельная рана — в `data/wounds.js`, что делает SPECIAL — в `data/special.js`.

## Единая шкала: PL

Чтобы сравнивать копьё с кольчугой и бронзу с железом, у всех вещей одна ось — уровень силы (PL). Один уровень — это ×1,2:

- **атака** оружия — к урону за тик: `log₁.₂((dmg / cd) / (dmg / cd дубины))`. Дубина — PL 0;
- **защита** брони и щита — к тому, сколько держится владелец: `log₁.₂(1 / (1 − armor))`, и так же для блока.

Атака и защита складываются: сила бойца — урон за тик, умноженный на время, которое он продержится. Копьё и щит — сумма двух; двуручному оружию нужно окупить щит, для которого не осталось руки. Арена это подтверждает: в честном прогоне (`--fair`) +1 PL атаки и +1 PL защиты дают почти одинаковую прибавку к шансу победы.

Качество тоже в PL: +1 даёт к атаке ~0,8 PL, +2 — ~1,4, +3 — ~2, +4 — ~2,9. Это сравнимо со ступенью материала, но стоит в разы дороже, как волшебные вещи в D&D.

Ориентир для новых тиров (`rules.js`, `tierPL`): каждый тир материала поднимает атаку примерно на 1 PL, а защиту брони — на 1–1,5 PL.

## npm run items

```bash
npm run items                    # таблица и находки
npm run items -- --csv items.csv # то же в CSV для таблиц
npm run items -- --strict        # ошибка, если есть ✗ (для CI)
```

Таблица показывает для каждой вещи тир, атаку, выстрел, защиту, тепло, работу, итоговый PL, цену, «справедливую» цену по кривой, стоимость сырья по рецепту и прочность. Кривая цены строится по самим вещам: `ln(цена) = a + b × PL` отдельно для оружия и для брони. Новой вещи она подскажет цену, а у старой покажет, насколько та выпадает.

Находки:

- **✗** — вещь хуже другой во всём (атака, защита, руки, шаг, прочность, работа) и стоит не меньше. Её никто не должен выбирать.
- **⚠ в бою хуже** — вещь проигрывает другой в бою и держится только на работе или прочности. Для топоров и молота это нормально, если так задумано.
- **⚠ вне коридора тира** — вещь слабее или сильнее, чем положено её тиру.
- **⚠ сильнее вещи тира выше** — нижний тир перекрывает верхний («дубина лучше мифрила»).
- **⚠ двуручному не хватает** — двуручное слабее, чем слабейшее одноручное своего тира со щитом.
- **⚠ цена** — больше чем вдвое мимо кривой.
- **·** — вещь стоит дешевле своего сырья: делать её на продажу невыгодно.

## npm run arena

Тысячи поединков без графики. Бой настоящий: задача `fight` из игры, удары, выстрелы, броня, щиты, криты, уклонения и износ. Мозг не участвует: никто не бежит и не зовёт на помощь, поединок идёт до конца. Каждый бой задаётся сидом и своим номером, поэтому результат не зависит от числа потоков.

```bash
npm run arena                          # 10 000 боёв: все расы, SPECIAL по расе, случайный навык
npm run arena:fair                     # только снаряжение: люди, SPECIAL 5, навык 0,5
npm run arena -- --fights 50000 --tiers 2
npm run arena -- --foes monsters,wolf,bear --foe-share 0.5
npm run arena -- --quality mix --armor any --distance 12
```

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `--fights` | 10000 | сколько боёв |
| `--tiers` | все тиры, где есть оружие | в каких тирах драться |
| `--races` | all | кто дерётся (`human,orc,…`) |
| `--stats` | rolled | SPECIAL по пределам расы или `norm` — все 5 |
| `--skill` | random | навык 0–1 случайно или одно число для всех |
| `--armor` | tier | броня своего тира (или ближайшего ниже, где она есть), `any` — любая до тира, `none` |
| `--shield` | 0.5 | шанс щита у одноручного |
| `--quality` | 0 | `mix` — смесь +0…+3 |
| `--cross` | 0.2 | доля боёв, где у второго снаряжение следующего тира |
| `--foes`, `--foe-share` | — , 0.3 | драться ещё и с существами (`monsters` — все чудовища налётов) |
| `--distance` | 8 | клеток между бойцами на старте: от неё зависит, сколько успеют выстрелить лук и праща |
| `--max-ticks` | 3000 | дольше — ничья |
| `--seed`, `--jobs`, `--out` | arena, ядра, `runs/arena-<время>` | |

Отчёт ложится в `runs/arena-<дата-время>/`: `report.html`, `summary.json` и `fights.csv` (строка на бой, с обоими бойцами). В отчёте:

- **При прочих равных** — логистическая регрессия исхода по разнице двух бойцов. Она показывает, сколько к шансу победы даёт +1 PL оружия, +1 PL защиты, +1 к каждой букве SPECIAL, +0,1 навыка и вдвое более крепкий вид, и сколько это в PL оружия. Это курс обмена: сколько Силы орка покрывает ступень материала. Числа больше 10–15 п. п. — это наклон в равном бою, не готовый прирост.
- **По тирам**: оружие, набор в руках (с щитом и без), броня, щит у одноручного, матрица «кто кого». «Доминирует» значит, что весь 95% интервал доли побед выше 55%, «отстаёт» — что весь ниже 45% (пороги в `rules.js`, `arena`).
- **Расы**: доля побед и матрица раса против расы при снаряжении одного тира.
- **Навык и SPECIAL**: доля побед по своему навыку, по разнице навыков и по значениям букв. Это сырые доли, в них смешаны расы. Чистый вклад каждой буквы — в регрессии.
- **Тир против следующего**: как часто слабое снаряжение побеждает сильное. На это и стоит смотреть, когда добавляется новый материал.
- **Против существ**: доля побед вооружённого против каждого существа, по тирам и по оружию.

## Как добавить оружие или материал

1. Запись в `data/items.js`: id, название, слот, руки, значок.
2. Строка в `data/balance/weapons.js` или `armor.js`: тир, форма, числа. Цену можно поставить по подсказке «кривая» из `npm run items`.
3. Рецепт в `data/recipes.js`, если вещь делают в поселении.
4. `npm run items`: вещь в коридоре своего тира, не перекрыта и не перекрывает чужой тир, цена у кривой.
5. `npm run arena -- --tiers <тир>` и `npm run arena:fair`: доля побед не уходит за пороги, тир ниже не побеждает чаще обычного.

Новый материал — это новый тир (`tier: 3` для стали, `4` для мифрила) и по строке на каждую форму, которая из него бывает. Коридоры для них уже есть в `rules.js`.

## Порядок правки

1. Поменять числа в `data/balance/`.
2. `npm run items` — нет ли новых ✗ и ⚠.
3. `npm run arena:fair` — снаряжение без влияния рас и навыков.
4. `npm run arena` — с расами, навыками и тиром против тира.
5. `npm test` — справочники сходятся, игра детерминирована. Правка чисел меняет игры с тем же сидом; это ожидаемо.
6. `npm run balance:standard` — как правка сказалась на колонии целиком.
