## Зачем

До этого в игре было два устройства ума. Поселенец (`agents/brains/colonist.js`) — utility AI: каждый вариант получает оценку, лучший становится задачей, задача живёт по циклу (`agents/lifecycle.js`: сделано · заблокировано · невозможно · прервано), думает он по событиям (`agents/attention.js`). Звери — по мозгу на повадку (`predator`, `mule`, `vermin`, `spirit`), каждый — конечный автомат внутри одной функции; задачи у них только подписи для карточки. Чтобы сделать «хищника, который ест падаль и спит зимой», нужен был новый мозг.

Теперь поведение — запись в каталоге, а вид — список записей. Ум один и тот же для всех видов, которые так описаны; он спрашивает у каждого поведения из списка, чего оно хочет, и исполняет победителя. Отдельная повадка отрабатывается отдельно, а не правкой мозга целиком.

## Как устроено

Три места, как у работ (`data/jobs.js` называет `runner`, `agents/jobRunners.js` его делает):

| Где | Что |
|---|---|
| `data/behaviours.js` | **Каталог**: `{id, label, band, task, keep, requires, note}` — для таблиц и проверок. Таблица «Существа → Поведения». |
| `agents/behaviours/<id>.js` | **Код** под тем же id: `want(w, a, ctx)` — хочу ли и насколько; `step(w, a, task)` — как делаю; `enter`, `exit` — хуки задачи. `index.js` собирает их в `ACTS` и сверяет с каталогом при загрузке. |
| строка вида | `brain: 'tabled'`, `behaviours: ['bolt', 'graze', …]` — что умеет, в порядке выбора; `heart` — раз в сколько тиков думает (пусто — каждый). Готовые списки — `WAYS` в `data/behaviour.js`. |

`want` возвращает список вариантов `[[task, score, why], …]` или `null` — ровно те кортежи, из которых поселенец собирает свои `opts`. Поведение может предложить несколько вариантов (работа — по варианту на каждую вакансию) или чужую задачу: `sniffHay` предлагает `graze` в режиме `hay`. Задача — `{id, mode?, …}`; если выбран тот же `id`, что и у текущей, объект задачи сохраняется (место, прогресс), меняется только `mode`.

Задачи поведений регистрируются в `TASKS` (`agents/tasks.js`) рядом с написанными вручную, поэтому карточка, сохранение и чужие мозги видят их как любые другие.

Ум `tabled` (`agents/brains/tabled.js`) за тик:

1. тело: существо с потребностями — полное (`agents/body.js stepBody`: голод, холод, заживление), без них — только жар;
2. выбор: полный — раз в `heart` тиков или когда задачи нет; верхние две полосы — каждый тик;
3. задача: `lifecycle.syncTask` (закрыть прерванную, войти в новую), шаг задачи, снова `syncTask`.

Выбор записывается в `a.why` (что, оценка, почему, полоса), как у поселенца; в списке зверей на панели пока видна только задача.

## Полосы: очередь дел и тревоги

Каждое поведение лежит в одной из четырёх полос (`band`): `reflex` → `red` → `yellow` → `routine`. Ум берёт **первую полосу, где есть хоть один вариант**, и выбирает только внутри неё:

| Полоса | Что там | Пример |
|---|---|---|
| `reflex` | то, что не ждёт раздумья | огонь под ногами, удар по себе |
| `red` | красная тревога: враг, стая, налёт | `bolt` — бежать |
| `yellow` | жёлтая: тело на пределе, свой в беде, окрик | `alert` — насторожиться, `sniffHay` |
| `routine` | очередь дел | `leave`, `rest`, `graze`, работы |

Так тревога **прерывает** очередь, а не соревнуется с ней; когда тревога кончилась (поведение перестало предлагать), ум возвращается к очереди. Внутри полосы побеждает оценка плюс `keep` текущей задачи; при равенстве — первая в списке вида. Задача, которая только что кончилась неудачей, на время не выбирается (`agents/lifecycle.js skips`).

Числа предложений и повадок лежат в `data/behaviour.js` (`WANT`, `GRAZE`) и правятся в таблице «Повадки существ».

## Как добавить поведение

1. Строка в `data/behaviours.js`: `{id, label, band, requires: ['flee'], keep: 0, note}`. `requires` — поля строки вида, без которых поведение не записать: `npm test` откажет виду, у которого их нет. `task: false`, если задачу даёт другое поведение или общая задача из `agents/tasks.js` (`leave`).
2. Файл `agents/behaviours/<id>.js`: `export const <id> = {want, step, enter?, exit?}`; добавить в `ACTS` в `agents/behaviours/index.js`.
3. Числа — в `data/behaviour.js`, не в коде (`tools/check-layers.mjs` считает числа в логике).
4. Записать в список нужных видов (`WAYS` или строка вида), прогнать `npm test` и сравнить след зверей до и после.

Общие объекты — стая (`agents/carcass.js`), стадо (`agents/wildHerd.js`), отряд (`agents/squad.js`) — остаются системами: поведение в них вступает (`chase` присоединяется к охоте стаи), а не носит их в себе.

## Как добавить вид

Травоядное: `brain: 'tabled', behaviours: [...WAYS.grazer]` (или `herdGrazer`, если у вида есть `herd`), блоки `flee`, `grazes`, `leaveChance` — всё, что читают эти поведения. Остальное — как в [Как добавить новое](ADDING.md). Порядок в списке — порядок выбора; список правится в таблице «Монстры и звери → Поведения».

## Детерминизм и скорость

Порядок вызова `want` — строго порядок списка вида; при равной оценке побеждает первый. Поэтому правка списка в таблице меняет прогон при том же сиде, как любая правка строки (`npm run determinism`). Перенос травоядных с мозга `grazer` на `tabled` сделан так, что след зверей (положение и задача каждого на конец каждого дня, 3 сида × 8 дней) совпал тик в тик.

Звери пока думают каждый тик, как и раньше. `heart` в строке вида разрежает полный выбор, тревоги при этом смотрятся каждый тик; побудки по событиям (`agents/attention.js wake`) для зверей — впереди.
