## Балансный прогон

Стандартный прогон — с ним сравниваем каждое изменение баланса:

```bash
npm run balance:standard
# то же самое полностью:
node tools/balance.mjs --seeds 10 --days 30 --vary raids=off,rare,often --set predators=many
```

Три варианта набегов (нет, редкие, частые) при стаях волков, по 10 сидов на 30 дней, всего 30 игр. На двух ядрах занимает около 5 минут. Отчёт ложится в `runs/<дата-время>/report.html`. Чтобы положить его в свою папку, добавьте `-- --out runs/имя`.

Свои прогоны:

```bash
npm run balance -- --seeds 12 --days 30                         # базовые настройки меню, 12 сидов
npm run balance -- --set raids=often --set predators=many       # поменять настройки для всех игр
npm run balance -- --vary raids=off,rare,often --seeds 10       # сравнить варианты
npm run balance -- --vary raids=rare,often --vary stock=poor,normal   # варианты перемножаются
```

Параметры: `--seeds N` (сиды 1…N), `--seed-base K` (сдвиг сидов), `--days N`, `--set ключ=значение` (любой ключ стартового меню из `data/presets.js`, например `size=large`, `colonists=5`, `climate=cold`), `--vary ключ=a,b,c`, `--jobs N` (потоков, по умолчанию все ядра), `--out папка`.

Игры идут в рабочих потоках, по одной на ядро. Результат — в `runs/<дата-время>/`:
- `report.html` — отчёт: итоги по вариантам, доля выживших поселений по дням, любой показатель по дням (медиана и разброс между сидами), причины смертей, скорость расчёта;
- `runs.csv` — строка на каждую игру: выжила ли, на какой день пала, все показатели на конец;
- `days.csv` — строка на каждый игровой день каждой игры, для своих графиков в таблицах;
- `summary.json` — то же, что в отчёте, для скриптов.

Что измеряется, задаёт справочник `data/metrics.js`: добавленная туда строка сама появится в CSV, отчёте и выборе показателя. Игра без экрана запускается функцией `simulate(cfg, {days})` из `src/headless.js`.

На средней карте день игры считается примерно за секунду, игра на 30 дней — за полминуты на ядро.

## Стресс-тест

Отвечает на вопрос «сколько существ потянет движок». Каждый сценарий идёт в своём процессе Node, 1200 тиков (игровой день), без миграций и набегов: толпа ровно та, что поставил сценарий.

```bash
npm run stress                                  # быстрый набор, около минуты
npm run stress:full                             # сетка: 5 размеров карты × 8…1000 поселенцев в одном лагере
npm run stress:check                            # опорный сценарий mixed-100 укладывается в 6 мс (скорость 8×)
node tools/stress.mjs --only camp-50,mixed-200@huge   # любые сценарии
node tools/stress.mjs --profile mixed-300       # CPU-профиль: какие функции съедают тик
node tools/stress.mjs --ticks 600 --out runs/stress   # короче прогон; таблица ещё и в stress.csv
```

Сценарии называются `вид-число[@карта]`:
- `camp-N` — N поселенцев в одном лагере. Худший случай: все друг другу соседи.
- `mixed-N` — N объектов: 30% поселенцев в лагере, 55% оленей и зайцев и 15% волков (стаями по четыре) по всей карте. Похоже на живую карту.
- `herd-N` — 8 поселенцев и N оленей по всей карте: существ много, соседей у каждого мало.

Карты: `small` 96×72, `medium` 128×96 (по умолчанию), `large` 192×144, `huge` 256×192, `x384` 384×288, `x512` 512×384.

**Бюджет тика.** Игра делает тик раз в 50 мс при 1×. Значит, тик вместе с отрисовкой (около 1 мс) должен укладываться в 50 мс при 1×, 25 мс при 2×, 12 мс при 4× и 6 мс при 8×. Колонка «скорость» в таблице — самая быстрая скорость, которую тянет сценарий.

**Опорный сценарий — `mixed-100`.** Целевой потолок игры — 100 объектов на карте с запасом под новые механики. `npm run stress:check` падает, если он перестал укладываться в 8×. Запускать после каждой заметной фичи и сравнивать с таблицей ниже.

Замер 20.10.2026, облачная машина на 2 ядра (на обычном компьютере цифры не хуже). «До» — сборка `b923ff1`, «после» — индексы вместо перебора (ветка `perf/indices`):

| Сценарий | Карта | мс/тик до | мс/тик после | p95 после | Скорость после |
|---|---|---|---|---|---|
| mixed-30 | 128×96 | 1,6 | 1,2 | 4,3 | 8× |
| **mixed-100** | 128×96 | **2,9** | **2,2** | 6,1 | 8× |
| mixed-300 | 128×96 | 10,6 | 7,0 | 13,2 | 4× |
| camp-30 | 128×96 | 1,1 | 1,3 | 4,2 | 8× |
| camp-100 | 128×96 | 4,3 | 3,0 | 7,1 | 8× |
| camp-300 | 128×96 | 30,0 | 14,2 | 23,4 | 2× |
| herd-1000 | 256×192 | 13,6 | 12,6 | 23,2 | 2× |
| mixed-100 | 512×384 | 4,4 | 4,2 | 13,2 | 8× |

Разброс между запусками — около ±0,5 мс на малых сценариях; сравнивать лучше два прогона подряд на одной машине.

Что показала сетка (`stress:full`):
- **Размер карты почти не влияет.** На 512×384 (в 16 раз больше средней) поля стоят 1–3 мс, навигация меньше 0,3 мс; дольше только генерация — около 3 с.
- **Решает плотность толпы.** Время растёт примерно как квадрат числа соседей: 1000 оленей вразброс — 21 мс, в одной куче — 94 мс; 1000 поселенцев в лагере — около 300 мс.
- **Откуда был квадрат** (профиль `camp-300`): `separate` перебирал пары по полосе x, `attackerOf` для каждого просматривал весь список существ. Теперь расталкивание идёт по сетке, а «по id», «стая», «вид», «кто кого атакует» — из индексов `agents/lookup.js`; отпечаток мира тот же тик в тик.
- **Что осталось:** `nearestHostile` ищет врагов среди всех соседей, а в лагере соседи все свои; `decide` каждого поселенца перебирает все варианты. Это лечится на уровне групп (тревога колонии, стада), а не индексами.
- **Защита:** `tools/check-layers.mjs` (в `npm test`) не пропускает новый перебор `w.agents` в коде, который работает для каждого существа каждый тик (`agents/brains/`, `tasks.js`, `jobRunners.js`, `combat.js`, `movement.js`, `data/jobs.js`). Дешёвый перебор (его делают только духи, караван, крысы) помечается на строке: `// scan: почему дёшево`.

## Проверка справочников

`tools/check-data.mjs` (входит в `npm test`) проверяет, что все ссылки между записями сходятся: ресурсы в ценах и рецептах, строки таблиц `data/balance/` у предметов, постройки в `requires` и `needs`, мастерские у рецептов и работ, значки предметов, мысли у еды. Ошибка останавливает тест с понятным текстом, а предупреждение говорит о записи, которая в игре никогда не появится (ресурс ниоткуда не добывается, предмет нельзя сделать).

## Проверка логики

`tools/logic-check.mjs` (входит в `npm test`) собирает маленькие сцены на ровной пустой карте и проверяет правила, которые нельзя нарушать: хищник не бьёт издалека, несъедобный груз не становится сытостью, груз не мешает ответить на нападение, спрятавшуюся нечисть не бьют, никто не срезает угол между скалами, яд действует на всех, жаростойкий зверь не бежит от тёплой земли, караван без дороги не считает себя пришедшим, старая отметка застревания не мешает новой цели, волк не идёт к чужой добыче, совет видит кости от охоты. Сцены T18–T22 проверяют отряды налётчиков: у отряда одна цель, вожак и роли; при больших потерях и гибели вожака он отступает; противника держат и не мечутся; грабитель идёт к складу мимо защитников; пришедшие за одним идут за ним и уходят после расправы. Сцены T27–T31 проверяют туши и охоту стаей: добыча остаётся тушей, и стая ест из неё; голодный зверь возвращается к недоеденной туше; охотник отбивает тушу у сытых зверей; в погоне есть ведущий и загонщики, а охота закрывается одним итогом; неубранная туша в темноте поднимает упыря. Сцены T23–T26 проверяют совместные действия: одиночку в опасном лесу сопровождают; раненого перевязывают, и он это помнит; выздоравливающий уступает койку; при опасности ссору откладывают. Сцены T12–T17 проверяют резервы и жизненный цикл: к занятому верстаку второй не идёт, лишнему раненому койки нет, одно тело несёт один, прерванное дело отдаёт свои резервы, прерванный сбор продолжается с того же места, отказавшее дело не берут снова сразу же. Сцены T82–T84 проверяют правки после слияния World: пауза после «враг скрылся» держит только того врага, а на нападение другого отвечают сразу; удар налётчика — нападение, под ним не копают глину; выспавшийся до рассвета досыпает, а не идёт в лес.

## Поведенческие метрики

К ним добавлены «толпа» (доля работающих на самом людном деле) и «ночь без огня» (ночные тики без дров) — мерило наряда (`settlement/plan.js`).

Балансный прогон, кроме запасов и смертей, считает, как ведут себя существа (`settlement/behaviour.js`, группа «Поведение» в `data/metrics.js`): недопустимые состояния (существо в скале, в воде, за картой, груз не сходится — должно быть 0), простой и время в тревоге в процентах, смены дела и остановленные дела на человека в день, итоги поручений (доля сорванных — заблокировано или невозможно, и сколько на человека в день доведено, заблокировано, невозможно, прервано), отказы «пути нет» (всего и у поселенцев), время реакции на нападение и нападения, оставшиеся без ответа, исходы визитов отрядов налётчиков (цель достигнута, отступили, разбиты), охоты стаей (сколько в день, доля удачных), туши на земле и поднявшиеся из них упыри, совместные действия (доля времени в сопровождении, сопровождения в день, перевязки, уступленные койки, отложенные ссоры, забытые обиды). В консольной сводке видны простой и недопустимые состояния, остальное — в `runs.csv`, `days.csv` и отчёте.
